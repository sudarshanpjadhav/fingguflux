# Versioning & Compliance

FingguFlux adheres to a strict **Hardened Versioning Contract** to ensure system stability across updates.

## 1. The Version Guard

Every `mapping.json` generated by the compiler includes a `_version` field. On initialization, the framework adapters (React, Vue, Svelte) validate this against the `version` prop provided in the root provider.

### Why this is critical:
If your CSS build and your Mapping build get out of sync (common in CI/CD), you might have mismatched hashes. The Version Guard identifies this instantly and warns you in the console, preventing "silent breakages."

## 2. Extreme Mode Cautions

While Extreme Mode offers maximum security and minification, it introduces specific developer constraints:

- **No Inspection Reliance**: You cannot write `document.querySelector('.ff-btn')` in your client scripts, as `.ff-btn` will be hashed. Use `data-ff-*` attributes for DOM selection.
- **Strict Mapping**: In Extreme Mode, missing a mapping for an `ff-` class is a **Fatal Error** in development. This forces architectural discipline.

## 3. SemVer Commitment

- **Patch**: Security fixes and performance optimizations. No token changes.
- **Minor**: New components, new motion utilities, or new theme tokens.
- **Major**: Changes to the internal hashing algorithm or compiler engine logic.
